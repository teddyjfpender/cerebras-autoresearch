## What the implementations change

- **Vector-column chain:** use the existing intermediate vector as output accumulators, apply strided FP32 vector FMAs across output channels, then execute the complete bias/ReLU/residual epilogue and store every frame. Timers, five distinct input frames, and output coverage stay fixed.
- **Expanded vector chain:** explicitly expand eight vector FMAs for the small K=8 profile. Its marginal gain over generic vector accumulation is separately visible in the screen history.
- **GEMV expansion:** replace the local map callback with literal FP16 FMAs while preserving DSR progression, reduction communication, initialization, and repetition controls. The alignment variant additionally tests padded/aligned storage.
- **GEMM experiments:** expand columns or the complete local tile while retaining communication and per-K descriptor progression. Neither was retained.

The trusted evaluator stayed at `016268587f080dcae42acd7cf964f5606b303515b230681891b4e6e12950233d` throughout paired optimization. Candidate CSL and metadata identities were frozen. The orchestration helper was refined between invocations; it is outside the trusted numerical/scoring capsule.

## Developer-experience findings and changes

| Finding | Change / evidence |
| --- | --- |
| Repeating the same full baseline wastes iterations | New `tools/run_campaign.py` shares a full baseline across candidates on a cell and filters slow/oversized screens before full validation |
| Long campaigns need recovery | Atomic checkpoints reuse completed runs and decisions; cached receipt, evaluator, candidate source, and metadata changes are rejected |
| Interrupted compiler work must remain visible | Deliberate SIGINT preserved a cancelled GEMM receipt; resume reused the confirmed chain and restarted incomplete work |
| An attached long output connection failed with a broken pipe | Failed GEMV receipt retained; detached VM execution with `nohup` and persistent `console.log` completed the campaign |
| Terminal output must not block durable logging | After the frozen campaigns completed, moved terminal receipt output after journal append and tolerated a broken pipe; regression test reproduced the bug before the fix and passed afterward |
| Retry should focus on unfinished work | `--retry-failed` retains failed attempt history and skips confirmed cells; host tests cover both behaviors |
| Status should be readable without taking the simulator lease | Host `--status` reports checkpoint progress and explicitly does not claim process liveness |
| Original plans may reference ignored local baselines | A portable `fresh-plan.json` measures every baseline anew on another checkout |
| Git capture can fail independently of source capture | Some attached receipts contain `unknown`; later detached receipts capture the revision. Historical fields are untouched; source/evaluator capsules remain available. Root cause of the earlier missing Git fields is unconfirmed |
| Iteration timing needs a precise definition | Documented `experiment_wall_seconds` as SDK subprocess time, excluding preparation, provenance, hashing, and journal overhead |

See the [campaign workflow](campaigns.md) for persistent logs, retry, status, and export commands.
